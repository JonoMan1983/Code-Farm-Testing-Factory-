Process · Figma Workflow · AI-Assisted Prototyping

The Day-to-Day Build Process

How a flow actually gets built day-to-day on the Pantelotteriet mobile app and raffle site — the Figma structure, the journey-documentation habit, and the AI-assisted prototyping step that static frames can't cover. Diagram below is an illustrative explainer, not an actual screen.

01

Figma Structure

One cover page indexes every flow canvas. Repeating rows, fields, and dropdowns are built once as components with prefix/suffix slot variants, then reused everywhere instead of redrawn.

02

Journey Mapping

Every build gets documented as a numbered set of user journeys — registration through to claim, profile, support, history — each scoped in a single line covering the happy path and every edge case before a screen gets drawn.

03

AI-Assisted Prototype

A self-contained, hand-coded HTML prototype — real tab switching, live countdown logic, and state transitions — built with Claude Code to pressure-test flows and timing that static Figma frames can't simulate.

04

Dev Handoff

Flows, edge cases, and timing logic ship to engineering already proven against real interaction — fewer surprises once build starts.

Process Case Study · AI-Integrated Workflow

From Brief to Build: An AI-Assisted Design Process

How AI tools get woven into a real production workflow — not as a gimmick layered on top, but as a structural part of how decisions get made, validated, and shipped faster.

01

Brief & Strategy

Claude is used to interrogate the brief — surfacing edge cases, user goals, and competitive context before a single pixel is drawn, turning a vague ask into a scoped problem statement.

02

Visual Ideation

AI image generation produces a wide spread of visual directions in the time it would take to source one moodboard, giving stakeholders more to react to, earlier.

03

Design & Iteration

Figma's AI tooling handles auto-layout inference and component consistency checks, freeing time for the judgment calls that actually need a designer — hierarchy, flow, and tone.

04

Prototyping & Handoff

Claude Code turns static frames into clickable, logic-aware prototypes and dev-ready annotation — shortening the gap between "this is the idea" and "this is buildable."

Before

Manual moodboarding, sequential review cycles, and handoff documentation written from scratch for every project.

After

Parallel exploration, AI-drafted rationale and documentation as a starting point, and more design time spent on judgment rather than production mechanics.
